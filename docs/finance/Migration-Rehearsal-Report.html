Scope and method

A read-only repeatable-read transaction exported the source snapshot used by pg_dump. The custom backup was encrypted with AES-256-GCM; its key was wrapped for the current Windows account. Separate databases on a private loopback PostgreSQL 17.4 instance were restored with replication/background workers disabled. No application or business worker was started.

The schema comparison covers logical column order, types/defaults, constraints, indexes, triggers, routines, views, enums, extensions and sequences. Full ordered row fingerprints, large objects and private invoice header/item evidence were compared. Original migration-table schema was also retained.

Logical restore comparisons

PostgreSQL removes physical slots left by dropped columns and can rewrite equivalent no-length varchar-to-text literal casts during restore. The comparison preserves logical order and all recorded definitions. Thirty-nine exact cast pairs were verified equal directly in PostgreSQL; all other compared definitions matched. Early rehearsal checks stopped before any migration while these comparison rules were corrected.

Rollback and recovery frontier

The down rehearsal applies only to unused empty registries. The migration metadata sequence can keep consumed IDs after down; original business sequences remain unchanged. A separate fresh restore proved exact recovery of all original sequences and data. Once real governance or financial evidence exists, destructive down may be forbidden; use the approved forward-repair and recovery process.

Preserved controls and remaining approval

  • Actual company-admin policy, configuration and release decisions remain unreceived; all policies stay inactive.
  • This backup restore uses the private administrator and intentionally omits original ownership and ACL restoration. Production roles, permissions and access-model recovery remain to be verified separately.
  • No application server, source producer, worker, bank/provider, TIRAMIS, fiscal or real authentication flow was started. End-to-end operational cutover is not certified.
  • The cloned balances were preserved and reconciled to the source, but no financial opening certificate, bank truth, IFRS17/IFRS9 model, company reporting scope or go-live policy is approved.
  • Company-approved RPO/RTO, backup retention, key recovery, operating windows, capacity and aftercare targets remain unset. The measured whole-run duration is not an accepted recovery SLA.
  • The twelve migrations remain unapplied to the original development database. Logical switch, live posting, B15 and independent Finance service extraction are not authorized by this rehearsal.
