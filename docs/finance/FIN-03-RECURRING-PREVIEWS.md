# FIN-03 recurring allocation previews

The scheduler creates inactive calculation evidence, checks allocation branches against an exact reviewed company master and source association, and does not read actual balances or post to a ledger. It recovers the earliest missing eligible month on each hourly run, up to a 100-year recovery bound. Occurrence identity is the scoped schedule release and date. Immutable occurrence records include exact schedule and rule hashes, output lines, worker and authority; append-only audit rows record creation and held attempts.

Migrations `1797800000000-FinanceRecurringAllocationPreviews` and `1797900000000-FinanceAllocationPreviewReviews` add empty authority, occurrence, review and audit tables. They grant no authority. The scheduled worker does nothing unless `FINANCE_ALLOCATION_WORKER_ID` names a UUID with an enabled, unexpired authority bound to the exact reviewed schedule release and book. A V2 schedule pins a reviewed monthly rule, the company dimension releases, an explicit amount and currency. The worker rechecks the rule, schedule, book, company master and authority in the transaction and serializes concurrent attempts. V1 schedules are held until replaced by a reviewed V2 schedule.

The authenticated Finance setup API permits scoped company admins with current review authority to grant or revoke bounded worker authority. Authorized readers can inspect up to 100 recent company-owned previews; the portal setup screen displays their lines and permits an authorized reviewer to record an inactive decision. A different authorized preparer can use the reviewed occurrence to prepare an inactive journal candidate. The candidate still requires its separate approval and validation workflow, and the ledger rejects allocation-preview candidates.

The portal prepares signed source attestations from an independently reviewed, rechecked company master. A scoped delivery worker can retry the exact bytes against a configured Finance endpoint; a pinned Finance receipt signature must be verified and stored before another revision is prepared. Expired undelivered evidence can be archived in revision order, but is never treated as a current company snapshot. If the source key is no longer authorized, recovery remains held for controlled reconciliation. Worker grants, outbox records, receipts and delivery attempts remain scoped and auditable. The independent service has signed source and key-change endpoints and a verifier. Its read-only human API rechecks the portal session and an independent book grant on each request; deployment with a real portal session is not yet verified. Independent allocation execution remains disabled. Authenticated browser testing and the independent-service UI remain outstanding. Applying migrations or setting a worker ID does not authorize production posting.

For an isolated producer deployment, configure `FINANCE_SOURCE_ATTESTATION_KEY_ID`, `FINANCE_SOURCE_ATTESTATION_PRODUCER_ID`, `FINANCE_SOURCE_ATTESTATION_PUBLIC_FINGERPRINT` and `FINANCE_SOURCE_ATTESTATION_PRIVATE_KEY` through the deployment's secret-management system. The receiver must already have the matching scoped signing key. Configure the receiver receipt signer and the portal's pinned receipt public key, then configure a fixed `FINANCE_SOURCE_DELIVERY_URL` and an independently granted `FINANCE_SOURCE_DELIVERY_WORKER_ID`. HTTPS is required outside isolated tests. The producer issues evidence with a 15-minute validity. Selected products must have an explicit effective date and definition hash. The outbox records the exact signed bytes and does not contain the private key.

Before signing, the producer rechecks currently effective reviewed company masters and holds a snapshot that omits or changes their branch or product records. This is a fail-closed coverage check, not automatic consolidation of book masters; concurrently reviewed new masters and later changes still require operational reconciliation. A synthetic HTTP delivery test uses separate disposable portal and Finance databases, including lost-receipt recovery and a worker revocation during delivery. It does not constitute acceptance of any company environment.
